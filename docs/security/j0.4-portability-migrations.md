# Portable exports and reviewed destructive operations

Owner-authorized exports include canonical encrypted-record reconstructions,
messages, attachments/files, memory/vector records, knowledge relationships/evidence,
project/settings records, provenance, lineage, retention, tombstones, schema checksums,
and a safe projection of non-human identity definitions. Authentication keys,
sessions, delegations, tokens and vault values are not portable authority and are
not included. Definition reconstruction does not grant permissions.

The manifest hashes every file. Reconstruction validates owner/ID/path binding,
object content hashes, source/attachment linkage, and tombstone exclusion. Provider
identifiers remain metadata. File bytes use permanent object IDs independent of
the source adapter. Export is owner-authorized plaintext portability, not an
encrypted operational backup. Current size limits fail explicitly instead of
silently exporting only part of a record domain.

`GovernedMigrations` accepts a trusted repository-reviewed definition registry.
Requests contain only a registered ID, complete definition hash and backup ID.
The default runtime registry is empty: unsupported operations fail closed.
Definitions cannot be supplied through requests/model output/imports. The existing
runtime database role is retained; this is not an elevated SQL execution endpoint.

Execution requires an exact consumed J0.3 P4/Z4 one-use authorization, A3 owner
approval, validated unexpired backup without deletion obligations, matching schema
version, and matching affected-table snapshot. Affected tables are locked while
checking and applying the reviewed operation. Verification must return exactly one
true result; database/vector health is checked and metadata-only audit evidence
records definition hash and recovery ID. Any failure rolls back the data gateway
savepoint. Transaction-control SQL and unbacked domains are rejected.

The normal startup migration runner continues refusing destructive manifests.
Operators must explicitly review/register an operation through this governed path;
the implementation does not silently turn startup into a destructive migration
runner. Real privileged production DDL, online schema rollout and recovery to a
production target remain unsupported and fail closed. The development integration
registry uses synthetic data, not owner or production records.
