# J0.8 Event System

Protected baseline: `4c05f1d9522d4950e6f9b12a0087290ba74bd5fb` (J0.1–J0.7 Development GO).

## Permanent rule

Events are authenticated, validated facts/signals. They never grant capabilities, approvals, execution authorization, memory truth, or direct tool authority.

`SOURCE → INGEST → AUTHENTICATE → VALIDATE → DURABLE ACCEPT → ROUTE → AUTHORIZE CONSUMER → PROCESS → CHECKPOINT → EVIDENCE`

Any effect remains:

`EVENT → JARVIS DECISION → J0.3 → J0.7 → VERIFY → RESULT EVENT`.

## Architecture

J0.8 extends `@jarvis/events` with provider-neutral envelopes, type/schema registry, subscriptions, producer/consumer policy ports, authenticated external ingress, replay protection, durable outbox/inbox/delivery/dead-letter/schedule ports, bounded routing/retry/loop protection, replay, scheduler, health and owner-control inspection.

PostgreSQL is durable truth. Redis/BullMQ is transport only. Delivery semantics are at-least-once with durable idempotent consumers; no exactly-once claim is made.

Durable PostgreSQL state is added additively by migration 0011: events, outbox, inbox, subscriptions, delivery attempts, dead letters, schedules, ingress receipts and sequence checkpoints. Critical state/outbox insertion can share one database transaction.

## Security and privacy

- unknown event type/schema/producer fails closed;
- owner/project scope is mandatory and checked again at consumer routing;
- external ingress authenticates before durable privileged acceptance and maps owner/project from trusted producer configuration, never caller claims;
- source IDs/nonces are durably replay-protected;
- D5/local-only data cannot route to external consumers;
- sensitive payloads are minimized and never treated as instructions/authority;
- fake approval events cannot substitute for authoritative J0.3 state;
- event-triggered privileged effects require an authorized action port backed by J0.3/J0.7;
- replay applies current authorization and preserves original/replay evidence;
- logs/evidence/control-plane views redact secret-like fields and do not expose credentials.

## Reliability

Transactional outbox, durable inbox, claims/checkpoints, bounded exponential retry, deterministic stale-sequence handling, causation/correlation, max chain depth, dead-lettering, controlled replay, occurrence-key schedule dedupe, payload/producer/owner backpressure and graceful claim shutdown are required.

Crash windows are intentionally safe: unpublished outbox rows survive; publish-before-checkpoint may duplicate transport but inbox dedupes; consumer restart cannot duplicate a completed receipt; queue outage cannot delete accepted PostgreSQL state.

## Scope boundary

J0.8 provides generic synthetic/authenticated ingress and queue ports. It does not implement Gmail, Calendar, GitHub, Slack, phone, IoT, Kafka/NATS/Pulsar or production multi-region scheduling. J0.9 is not started.
