# J1.3 Model Orchestration Runtime

Baseline: released J1.2 `2e2302a9aa8553e4971db21842c858098183a233`.

## Objective

J1.3 composes the J0.6 provider-neutral model subsystem with J1.1 conversation/session authority and the J1.2 ContextEnvelope. JARVIS remains the authority; model output is content only.

## Runtime flow

J1.1 authorized turn -> J1.2 ContextEnvelope -> J1.3 policy/envelope/digest validation -> current-authority recheck -> deterministic J0.6 provider eligibility/routing -> bounded logical retry/fallback plan -> per-attempt authority/cancel/deadline recheck -> normalized result -> final authority recheck -> content-only result.

## Included

- provider/model registry reuse and validation
- provider-neutral optional descriptor metadata for family/revision/latency/quality/reliability/region/pricing-known
- deterministic balanced, cheapest, fastest, highest-quality, local/private preferred, pinned and fallback-chain routing strategies
- provider/model allow/deny/preference policy
- capability, locality, privacy, classification, context, token and cost eligibility
- J1.2 envelope binding, classification-ceiling enforcement and D5 generic-model denial
- honest estimated/actual/unknown cost representation
- shared operation-level attempt/token/cost budgets spanning retries and fallback
- operation-level timeout distinct from owner cancellation
- per-attempt cancellation and current-authority rechecks
- bounded retries and policy-safe fallback through J0.6
- runtime provider health and circuit-open recovery state
- per-attempt health observation so failed primary providers are tracked even when fallback succeeds
- digest-bound operation idempotency/correlation
- privacy-safe J1.3 audit metadata
- structured-output validation through a JARVIS-owned verifier
- second provider-compatible reference adapter with injected transport
- synthetic integration across J1.1, J1.2 and J1.3
- direct J1.3 security tests for privacy, emergency, error, malformed-response, untrusted-context and NEVER_STORE boundaries
- explicit A-T acceptance and full CI regression

## Schema decision

No J1.3 database migration is required. Provider health/circuit state and in-flight operation idempotency are runtime coordination state. Persisting prompt/model payloads or runtime circuit state would add unnecessary durable authority and retention risk. Foundation migrations 0001-0014 and the J1 migration extension remain unchanged.

## Security invariants

- current authority is checked before dispatch, before every retry/fallback attempt and after provider completion
- D5 is not admitted to generic J1.3 model orchestration
- the J1.2 classification ceiling cannot be exceeded by the model request
- an external provider cannot consume a ContextEnvelope whose disclosure target is not `external-ai`
- local/private disclosure targets cannot silently broaden to a less-private target
- private operating mode cannot silently broaden to an external model
- owner/project/turn bindings must match
- J1.3 never retrieves memory or executes tools
- retries/fallback cannot bypass locality/privacy/capability/health/cost/budget policy
- retries/fallback share one explicit operation attempt/token/cost bound
- unknown cost is explicit and denied by default
- late/cancelled results are rejected and cancellation claims remain honest
- operation-key replay with a different digest fails closed
- audit records carry metadata only, not prompt/context/model plaintext
- provider/model IDs are locators, not authority
- model output remains `acceptedAsContentOnly: true`

## Validation coverage

J1.3 validation includes deterministic routing strategies, allow/deny/pinned behavior, capability/context/cost rejection, D5/external privacy, classification ceilings, total retry/fallback budgets, operation timeout, cancellation before/during dispatch, authority invalidation between attempts, FREEZE/SHUTDOWN fail-closed authority, rate-limit/outage normalization, malformed provider output, structured-output contracts, circuit open/recovery, exact digest idempotency, audit privacy, untrusted context, NEVER_STORE handling, provider interchangeability and J1.1/J1.2 integration.

## Non-goals

J1.4 response generation, J1.5 persistence/history, J1.6 memory-aware conversation, J1.7 tool execution, J1.8 approval-aware execution, J1.9 full operating-mode behavior, J1.10 full streaming resilience, J1.11 final UI/mobile control center, and J1.12 final integration are not part of J1.3.
