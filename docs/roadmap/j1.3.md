# J1.3 Model Orchestration Runtime

Baseline: released J1.2 `2e2302a9aa8553e4971db21842c858098183a233`.

## Objective

J1.3 composes the J0.6 provider-neutral model subsystem with J1.1 conversation/session authority and the J1.2 ContextEnvelope. JARVIS remains the authority; model output is content only.

## Runtime flow

J1.1 authorized turn -> J1.2 ContextEnvelope -> J1.3 authority recheck -> deterministic J0.6 provider eligibility/routing -> bounded provider execution -> normalized result -> authority recheck -> content-only result.

## Included

- provider/model registry reuse and validation
- deterministic routing and allow/deny/preference policy
- capability, locality, privacy, context, token and cost eligibility
- J1.2 envelope binding and D5 generic-model denial
- operation-level timeout and cancellation
- bounded retries and policy-safe fallback through J0.6
- runtime provider health and circuit-open recovery state
- operation idempotency/correlation
- privacy-safe J1.3 audit metadata
- second provider-compatible reference adapter with injected transport
- synthetic integration across J1.1, J1.2 and J1.3
- explicit A-T acceptance and full CI regression

## Schema decision

No J1.3 database migration is required. Provider health/circuit state and in-flight operation idempotency are runtime coordination state. Persisting prompt/model payloads or runtime circuit state would add unnecessary durable authority and retention risk. Foundation migrations 0001-0014 and the J1 migration extension remain unchanged.

## Security invariants

- current authority is checked before dispatch and after provider completion
- D5 is not admitted to generic J1.3 model orchestration
- an external provider cannot consume a ContextEnvelope whose disclosure target is not `external-ai`
- owner/project/turn bindings must match
- J1.3 never retrieves memory or executes tools
- retries/fallback cannot bypass J0.6 locality/privacy/capability/budget policy
- late/cancelled results are rejected
- audit records carry metadata only, not prompt/context/model plaintext
- provider/model IDs are locators, not authority
- model output remains `acceptedAsContentOnly: true`

## Non-goals

J1.4 response generation, J1.5 persistence/history, J1.6 memory-aware conversation, J1.7 tool execution, J1.8 approval-aware execution, J1.9 full operating-mode behavior, J1.10 full streaming resilience, J1.11 final UI/mobile control center, and J1.12 final integration are not part of J1.3.
