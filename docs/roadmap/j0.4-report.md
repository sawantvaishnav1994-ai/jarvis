## Security invariants

No parallel authorization system was introduced. The identity RPC delegates to
`GovernanceEngine(PrivateDataGateway)`; only the security engine mints a one-shot
execution permit. Exact request/transient digests bind owner approvals without storing
the private payload in request history. Identity, authorization consumption, data and
audit share a PostgreSQL transaction. A storage savepoint rolls back failed changes
before sanitized denial evidence is retained. No model can grant itself access.

The development resource is exactly `owner-data`. Only bounded R2 `data.inventory`
is added to the standing-delegation allowlist; sensitive actions require explicit
escalation policy and fresh exact A3 owner approval. J0.3's R5/Z5/P5 denial remains.
No real financial, external connector or unrestricted agent capability is enabled.

Payloads use 256-bit AES-GCM data keys, 96-bit nonces and 128-bit tags. The DEK is
wrapped under a versioned KEK, with authenticated context. Backup encryption uses a
separate key. Tampered envelopes and unavailable keys never return plaintext fallback.
Metadata, size/equality leakage, JavaScript GC copies and host-root compromise are not
hidden by these guarantees. Common-secret rejection is deterministic but cannot detect
every arbitrary credential mislabeled as ordinary content.

Deletion is bounded to active database payloads/history/vectors/derived records. Its
`backupExpiryRequired` field is an outstanding obligation, not proof that backup copies
have expired. New attachment cascades use committed revocation plus separately authorized
file purge; shared or unmigrated attachment links are refused without changing active rows.
Expired reads fail closed, but physical retention maintenance remains unimplemented.

The object store and isolated restore target are outside the source database's atomic
commit. Encrypted orphans/uncertain outcomes are possible; they are not blindly retried.
Restores are restricted to preconfigured empty test targets, never request-supplied
destinations, and reject snapshots predating known deletion tombstones. Active sessions,
delegations and challenges are invalidated; separately supplied recovery keys are needed.
