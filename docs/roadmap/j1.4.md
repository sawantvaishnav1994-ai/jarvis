# J1.4 Response Generation and Turn Pipeline

Baseline: frozen J1.3 `721da16c4bb40f6ac1a4422b2fbb453f2db666da`.

## Objective

J1.4 composes J1.1 Conversation/Session, J1.2 Context Assembly and J1.3 Model Orchestration into one governed conversation-turn state machine. Conversation state never creates authority and model output remains untrusted content only.

## Canonical state machine

`ACCEPTED -> AUTHORITY_VALIDATING -> CONTEXT_ASSEMBLING -> MODEL_PENDING -> MODEL_RUNNING -> MODEL_RESULT_RECEIVED -> RESPONSE_PROCESSING -> COMPLETED`

Terminal/interruption states are `FAILED`, `CANCELLED`, `REVOKED`, `TIMED_OUT`, `SAFE_MODE_BLOCKED` and `EMERGENCY_STOPPED`. Invalid state transitions fail closed.

## Authority boundary

Current authority is rechecked before context continuation, model dispatch, after model completion, before response processing and before completion. Owner/session/turn/security-epoch bindings are immutable inputs. Revocation and security-epoch change terminate the continuation as `REVOKED`; SAFE MODE terminates as `SAFE_MODE_BLOCKED`; FREEZE and SHUTDOWN terminate as `EMERGENCY_STOPPED`.

## Context and model composition

J1.4 consumes a J1.2 `ContextEnvelope` through the context port and invokes models only through the J1.3 execution port. It does not rebuild retrieval, classification, minimization, provider routing, retries, fallback, provider health or cost policy. J1.2/J1.3 remain authoritative for D5, disclosure-target, locality, privacy, token and model eligibility rules.

## Content-only response boundary

A successful J1.3 result must be explicitly marked `acceptedAsContentOnly: true`. J1.4 can surface normalized model text as response content but does not grant model output authorization, approval, permit, policy authority, tool authority or memory-write authority. J1.4 results explicitly attest `toolExecutionCommitted: false`, `approvalCommitted: false` and `memoryWriteCommitted: false`.

## Idempotency and binding

J1.4 binds replay to owner, project, conversation, session, turn, security epoch, input digest, context digest and model-operation digest. An exact replay returns the same operation promise. Reusing an idempotency key with changed protected binding fails closed.

## Cancellation, late results and failures

Owner cancellation is checked before protected continuations. J1.3 remains the sole retry/fallback implementation. J1.4 maps model cancellation and timeout into terminal turn states and discards results that arrive after authority has become invalid. Failed, cancelled, revoked or timed-out turns never transition to `COMPLETED`.

## Streaming boundary

J1.4 defines ordered internal response events for later J1.10 integration. These events are not reconnect/resume infrastructure. Partial/content events cannot commit tools, approvals, memory or any other protected side effect.

## Persistence boundary

No J1.4 migration is required. Full conversation history belongs to J1.5. J1.4 adds no durable prompt/model payload store and does not create persistence for NEVER_STORE material.

## Audit boundary

J1.4 audit records contain correlation IDs, conversation/turn IDs, state, reason code and digest references. They do not include prompt bodies, context payloads, model text, credentials or secret material.

## Validation

J1.4 requires dedicated unit, integration and security/adversarial tests, explicit A-T acceptance, complete Foundation/J1.0-J1.3 regression, real PostgreSQL/pgvector, Redis/BullMQ, browser identity/device trust, recovery/outage and shutdown qualification.

## Non-goals

J1.5 persistence/history, J1.6 memory-aware conversation, J1.7 tool-aware conversation, J1.8 approval-aware interaction, J1.9 full operating modes, J1.10 full streaming resilience, J1.11 final conversational UI and J1.12 final integration are not part of J1.4. No production model credentials, external tool connectors or autonomous agents are introduced.
