# J1.10 — Streaming, Cancellation and Resilience

Status: ARCHITECTURE FROZEN FOR DEVELOPMENT

Baseline: combined J1.9 development checkpoint on top of J1.8 frozen `cf203bb71df1d4cb19e819546f2684201e04cc16`.

## Objective

Add reconnect/resume and cancellation coordination around the already-governed J1 conversation pipeline without introducing a second model retry engine, turn state machine, tool retry mechanism, approval authority, persistence authority, or side-effect replay path.

J1.3 remains provider retry/fallback authority. J1.4 remains turn-state and ordered response-event authority. J1.5 remains durable conversation/history authority. J1.7/J1.8/J0 remain the only protected execution path.

## Required invariants

- Stream cursors bind owner, project, conversation, session, turn and security epoch.
- Resume is read/replay of already-produced response events only.
- Resume never redispatches model, tool, approval or memory side effects.
- Ordered events are contiguous and monotonic; gaps, duplicates or binding changes fail closed.
- Current authority is revalidated before stream state is returned.
- Revocation, security-epoch change, SAFE MODE, FREEZE and SHUTDOWN invalidate protected continuation immediately.
- Client disconnect is not authority to retry protected work.
- Cancellation is propagated through existing AbortSignal boundaries and late results cannot commit protected effects.
- J1.3 remains the only model retry/fallback implementation.
- Tool unknown-outcome/idempotency/reconciliation remain J0.7/J1.7 responsibilities.

## Canonical flow

`trusted authority -> exact stream cursor -> current authority revalidation -> bound stream snapshot -> contiguous ordered event verification -> events after cursor -> client`

Reconnect/resume is therefore event recovery, not operation recovery.

## Failure and adversarial coverage

Tests must cover cancellation before/during delivery, stale epoch, cross-owner/project/conversation/session/turn cursor replay, malformed cursors, missing stream state, sequence gaps/duplicates, restrictive mode/emergency transition, late results after cancellation, reconnect after terminal state, provider failure, disconnect/reconnect, and proof that no protected side effect is replayed.

## Milestone boundary

J1.10 does not implement final Web UI behavior (J1.11) or final end-to-end qualification (J1.12). It exposes typed contracts that J1.11 can consume.
