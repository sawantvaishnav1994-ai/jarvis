## Required full-stack sequence

`tests/identity-e2e/identity.spec.ts` creates a synthetic owner and primary device,
requests a second device, proves it cannot authenticate before owner approval,
approves it with a fresh passkey, logs in, creates a restricted mock agent,
delegates one temporary permission, executes an allowed mock read through the
ToolGateway, denies a write and a critical action, revokes the second device,
denies reconnection and its old session, recovers the same owner with fresh keys,
denies old agent authority and shows recovery in audit history. It also tests
cookie security, browser errors, unsigned API calls and cross-origin denial.

The browser test requires `JARVIS_IDENTITY_E2E=1` and **a disposable fresh
installation**. Do not run it on your real owner database. CI supplies only
synthetic credentials. Traces, screenshots and video are disabled for this
security flow to avoid retaining session/recovery material in artifacts.
The six database identity integration tests create/drop only their own generated
`jarvis_identity_test_<random>` database; they never enroll the development owner.

## Known exclusions, not implied completion

Physical authenticator/hardware attestation and A4, remote production TLS/mTLS,
guest login UI, real voice/face recognition, automatic geographic risk, private
memory display, real tools, live AI agents, independent audit immutability,
host containment and full data/vault disaster recovery are not implemented here.
Approval of the **development identity slice** is distinct from all those gates.
