# J1.13 — Secure iPhone / PWA Access

Status: DEVELOPMENT

Protected baseline: J1 Core + Conversation v1 frozen on `f75ed2d2d712fe32e64eb161a7ecab73dcb34db1`.

## Objective

Make the existing J1.11 conversational Web surface usable from an iPhone without weakening the frozen J0/J1 authority model.

## Security rule

The hosted iPhone client MUST NOT contain local vault material, model/provider credentials, database credentials, Redis credentials, trusted-device secrets, Foundation session tokens, permits, or server-derived authority fields. A public/static preview may render the UI but MUST NOT pretend to execute the private JARVIS runtime.

## Current preview behavior

The public iPhone preview renders an interactive composer in PREVIEW mode. The input is clickable and accepts text. Submitting a message calls the isolated `jarvis-iphone-preview` HTTPS function and receives a PREVIEW_ONLY response. That function is origin restricted and has no model, memory, tool, approval, local-vault, database-credential, Redis-credential, or private-runtime authority.

This preview is intentionally not the real JARVIS conversation runtime. It exists to qualify mobile UX and the public HTTPS boundary without creating a fake security bypass.

## Remote runtime gate

Real conversation execution requires a qualified HTTPS backend that preserves: Root Owner authentication, trusted-device/session binding, HttpOnly server session authority, J0 policy/risk/approval/permit authority, J0.7 tool execution, PostgreSQL/pgvector and Redis behavior, revocation/emergency semantics, NEVER_STORE, audit/events, and outage/recovery behavior.

The current J1.11 development proxy reads local configuration/vault state and calls the API on localhost. It therefore MUST NOT be copied unchanged into a public serverless host.

The next implementation step is a production-safe remote transport/service-identity design that replaces filesystem vault access and localhost routing while preserving the same J0 authority and exact-bound security semantics.

## Exit

J1.13 is COMPLETE + FROZEN only after an exact candidate and exact-main qualification prove iPhone/PWA behavior and the secure remote backend boundary end-to-end. A UI preview alone is not J1.13 completion.
