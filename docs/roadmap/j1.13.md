# J1.13 — Secure iPhone / PWA Access

Status: DEVELOPMENT

Baseline: J1 Core + Conversation v1 frozen at `f75ed2d2d712fe32e64eb161a7ecab73dcb34db1`.

## Objective

Make the frozen J1 conversational Web surface safely usable from the owner's iPhone before the later full native multi-device milestone, without weakening J0 identity/device/session authority or introducing a second mobile authentication path.

## Scope

- responsive iPhone-first conversation shell;
- installable Progressive Web App metadata and icons;
- Add-to-Home-Screen support;
- HTTPS-only production posture;
- trusted-device enrollment/revocation reuse from J0;
- HttpOnly session handling preserved;
- safe reconnect/session-expiry/emergency UX;
- deployment topology separating Web/PWA presentation from any long-running API/worker infrastructure that cannot safely run as stateless serverless functions;
- production-readiness and iPhone browser acceptance tests.

## Non-goals

J1.13 does not implement native iOS background services, unrestricted microphone/camera access, push-driven agents, phone sensor orchestration, or full cross-device synchronization. Those remain part of the later phone/multi-device generation.

## Authority invariants

- J0 remains sole identity/device/session/policy/approval/tool authority.
- The browser/PWA remains a presentation client only.
- JavaScript never receives Foundation session tokens, approval proofs, permits, security epochs, or owner authority credentials.
- iPhone enrollment uses the existing trusted-device ceremony rather than a mobile-only bypass.
- A PWA install does not itself confer trust or privilege.
- Session expiry, device revocation, SAFE MODE, FREEZE, REVOKE, or SHUTDOWN must fail closed and render explicit restricted state.

## Development sequence

1. J1.13.0 architecture/deployment audit.
2. J1.13.1 responsive iPhone shell and safe-area behavior.
3. J1.13.2 PWA manifest, metadata, home-screen installability and icons.
4. J1.13.3 trusted-device/session UX hardening for iPhone Safari/PWA.
5. J1.13.4 secure remote deployment topology and environment contract.
6. J1.13.5 iPhone/Safari acceptance and release qualification.

## Exit rule

J1.13 is COMPLETE + FROZEN only after one exact candidate passes development checks, mobile/browser/security acceptance, and deployment qualification; `main` is non-force fast-forwarded to that exact SHA; and the exact-main qualification is green. Until then the frozen J1 release remains authoritative and J2 development must not depend on unqualified J1.13 behavior.
