## Scope implemented

J0.11 adds an explicit A–T acceptance catalog, a verifier that requires unique passing phase assertions plus the completed real-stack CI sequence, cross-foundation acceptance assertions, repeated critical governance/gateway/recovery tests and CI integration after all accepted J0.4–J0.10 gates.

No database migration is added. Migrations 0001–0014 remain the protected J0.10 schema chain. No accepted runtime architecture is redesigned.

## Evidence model

The candidate must pass, in one exact-SHA GitHub Actions run: clean setup, J0.11-owned formatting checks, static/contracts/security tests, repeated critical security tests, real PostgreSQL/pgvector integration, live API/worker/web readiness, Redis/BullMQ queue smoke, browser acceptance, Root Owner/device trust, J0.10 recovery drill, PostgreSQL/Redis outage and recovery, verified shutdown, J0.4 A–S, J0.5–J0.10 A–T and J0.11 A–T.

The J0.11 verifier writes `.jarvis/acceptance/j11-go.json` and deliberately refuses to run as a valid GO verifier without `J11_CI_SEQUENCE=complete`. This prevents local unit-only evidence from being represented as full J0.11 acceptance.
