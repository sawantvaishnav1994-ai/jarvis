# J0.7 Universal Tool Gateway

Baseline: `3eb07b904ac1e2f9be20a9e52008df824816b774`.

## Purpose
J0.7 establishes one provider-independent enforcement boundary for all future external actions. Models propose, agents request, JARVIS authorizes, the Tool Gateway executes, JARVIS verifies, and audit records evidence.

## Permanent path
`JARVIS Core -> J0.3 authorization -> J0.7 Universal Tool Gateway -> registered adapter -> external system`.

No model, agent, workflow, connector, interface, or internal service gains authority merely by naming a tool. Unknown tools fail closed. Source (`USER`, `MODEL`, `AGENT`, `WORKFLOW`, `SYSTEM`) never grants authority.

## Required semantics
- stable versioned tool definitions and explicit registry;
- validated canonical request/result envelopes;
- execution modes `INSPECT`, `SIMULATE`, `DRY_RUN`, `EXECUTE`, `VERIFY_ONLY`, `RECONCILE` with no silent escalation;
- exact normalized-input hash binding to J0.3 authorization;
- privacy/egress enforcement before external dispatch, with D5/local-only fail closed;
- least-privilege credential brokering using references/handles only;
- deterministic lifecycle and legal state transitions;
- idempotency conflict protection;
- bounded deadlines, truthful cancellation, retry policy based on operation semantics;
- timeout-after-side-effect represented as `UNKNOWN_OUTCOME`, followed by verification/reconciliation rather than blind retry;
- normalized result validation, independent verification, reconciliation and explicit rollback capability metadata;
- TOCTOU revalidation immediately before dispatch;
- emergency-control and delegation enforcement via the J0.3 authorization boundary;
- tool output is untrusted data and never becomes authority, approval, policy, or trusted memory automatically;
- safe audit metadata excludes credentials and unnecessary raw payloads;
- provider/model substitution cannot alter tool authority.

## Initial adapters
Only controlled synthetic adapters are required for Development GO: deterministic read, reversible/idempotent write, irreversible mutation, slow/cancellable operation, ambiguous timeout-after-side-effect, failure, malformed output, and credential/redaction probes. Real Gmail, calendar, browser, payment, phone, smart-home and robotics integrations remain out of scope.

## Persistence
J0.7 may use runtime/in-memory execution and idempotency stores for deterministic Development GO tests. New database tables are added only if durable semantics are required; existing J0.3 authorization/audit and J0.4 protected data structures must not be duplicated.

## Fail closed
Execution is denied if identity/authorization, exact input binding, resource scope, tool registration/version, privacy eligibility, credential authorization, input validity, approval where required, or pre-dispatch revalidation cannot be established.

## Acceptance
`tests/acceptance/j07-gates.json` is machine source of truth. The complete J0.1-J0.7 CI pipeline must pass on one exact candidate SHA. A green validation branch never merges or grants GO automatically. Merge requires explicit Owner approval, non-force fast-forward, and successful exact-main CI.

J0.8 and J1 remain locked throughout J0.7.
