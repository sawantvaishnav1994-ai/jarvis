# J0.8 Event System — Validation Notes

J0.8 extends the protected J0.7 baseline `4c05f1d9522d4950e6f9b12a0087290ba74bd5fb` without redefining established J0 authority, privacy, memory, model, or tool contracts.

Validation invariants:

- Events are facts/signals, never permissions.
- PostgreSQL is the durable event/outbox/inbox/schedule source of truth; Redis/BullMQ is delivery transport.
- At-least-once delivery is made safe through durable deduplication/idempotency rather than an exactly-once claim.
- External ingress authenticates the producer and resolves Owner/project scope from trusted mapping before durable acceptance.
- J0.4 D0–D5 policy is reused; generic durable event payloads are bounded to D0–D4 and secret-like evidence is minimized/redacted.
- Event-triggered privileged/external effects require current J0.3 authorization and execute only through the J0.7 Universal Tool Gateway.
- Replay preserves original history and is subject to current authorization and deduplication.
- Retries, chain depth, payload size, producer/Owner admission, subscriptions, scheduling, and graceful shutdown are bounded.
- Migrations `0011_event_system.sql` and `0012_event_retention.sql` are additive; the reviewed migration baseline is versions 1–12.
- J0.8 A–T is machine-verified only after J0.4, J0.5, J0.6, and J0.7 acceptance evidence is green.

This file records validation invariants only. It does not grant Development GO, authorize a merge, start J0.9, or issue J0 Foundation v1 GO.
